- [x] M1-T02b: **The painter's contract, measured (2026-11-14 morning; PR #12 `97cce94cf14a`, `measure-shadow-batches/v7/`; `scripts/painter_contract.py`, `painter_raw_words.py`, `painter_war_side.py`).** Inside the painter only the model calls `dDlst_shadowReal_c::imageDraw` makes reach the edge service (the draw functions are direct calls), so a management reads as: the retrace wait inside `JFWDisplay::beginRender` plus the clear and the 2D copy (P part 0: 4.1 / 5.8 / 4.0 M guest cycles at the busiest view / play / Outset — idle in guest time), the shadow models' viewCalcs with the painter's code between them (the prologue), then one region from the last of them to the painter's return (**the job: the draw lists, 1.71 / 1.33 / 1.76 M cycles**, ≈ 95 % of the painter proper), the delete/create handlers (219 cycles) and the execute loop (its regions 4.2 / 2.9 / 3.2 M; the scene's execute sub-phases besides). The execute loop writes only 17–64 of those words (WAW inside the window). **Who in the execute loop reads what the job wrote (regions a frame, each once per line):** `now` 63 (99 % of the readers write it too: a balanced push/pop stack), the `j3dSys` scratch line 47 (the model calls set `mModel`, `mMatPacket`, `mShapePacket`, `mTexture` before use; `mDrawMode`/`mMaterialMode` keep the last list's mode), the view matrix `j3dSys.mViewMtx` 14 (the execute-side viewCalcs; set in the prologue, two words touched by the job), `sNoUseDrawMtxPtr`/`sNoUseNrmMtxPtr` 34 (value-preserving swaps), `lightStatusData` and `g_env_light` 2–5, the game-info current window/view 1 (`dAttention_c::Run`, 12 k cycles in), one packet word of one actor; the audio and OS words only through the interrupts; play and Outset give the same list (41–47 regions on the scratch line, 28–34 on the pointers, 14 on the view matrix) plus one or two state-specific heap words (a packet flag, the window object). Reports: `v7/reports/<state>.painter{,.raw-words,.war}.txt`. **Reading:** a painter job is exact if (1) it runs on a snapshot of the state at its start, (2) the words above are handled: the balanced stack and the value-preserving swaps need nothing, the scratch fields nothing, and the view matrix, the modes, the game-info view and the packet flags end in values known at dispatch (to certify: pre-committed by the game thread, the job's own writes dropped), (3) the DSP steps inside the window are deferred to the join and the window's interrupts delivered on the game thread at the dispatch point with the time base presented as their due time (the painter's code and the handlers touch disjoint state: to certify with a handler region in the trace), (4) interrupts due after the painter are placed once its cycle count is known (a checkpoint at the uncertainty window), (5) the game thread's reads of the job's written pages stall until the join, its hardware accesses abort the batch, and a write by the job outside the certified set is a fatal report. The basis is certification plus runtime containment, not a universal validator: the same class as the native routines'. **Cost model at the busiest view:** ≈ 10–12 % of the frame gross on one worker at ≈ 10 % duty; the snapshot copies ≈ 0.3 %, the store-path page check ≈ 1–2 % (always on, or a module variant), the deferred DSP burst and the stalls to measure; ≈ 6–8 % net. **Caveat on M1-T01b's reader shares:** the trace's read list repeats lines the direct-mapped filter evicts, so the earlier class percentages were occurrence-weighted; counting a region once per line moves them by ≤ 3 points (other actors' execute 7.8 → 4.7 %; unread 44.1 % unchanged; `v6/reports/8-busiest.models.dedup.txt`); the job-window study and the first-reader classes were never affected
